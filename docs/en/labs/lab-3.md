# Lab 3 — Spring MVC REST: presentation cheat sheet

> English version. Polish 1:1 counterpart: [../../pl/labs/lab-3.md](../../pl/labs/lab-3.md)

## What was built

The catalog REST API: 6 DTOs (2 entities × create/update, read, list), 2 `@RestController`s, a global error handler, delete cascade, `catalog/request.http` (17 requests incl. error cases), springdoc/Swagger UI — all 3 tasks (8/8 pts).
Run: `cd catalog && ./mvnw spring-boot:run`; Swagger: `http://localhost:8080/swagger-ui.html`.

## Critical sections — likely questions

- **Why the create/update DTO has no id or category:** the id is generated by the application (`UUID.randomUUID()` in the entity — lab 2's "client" means our app relative to the DB, not the HTTP client), and the category comes from the `/categories/{id}/tests` address — exactly as the instruction says.
- **Collection DTOs** are separate wrapper records (`{"categories":[{id,name}]}`) — only id + a friendly name, per the requirement.
- **The URL hierarchy enforces the rules:** a test is created ONLY via `POST /api/categories/{id}/tests` (`POST /api/tests` does not exist) — "an element always belongs to a category" is guaranteed by the API shape. Single-test read/edit is flat: `/api/tests/{id}`.
- **Empty vs non-existing category:** first `findById` the category — missing → `404`; present but empty → `200` + empty list. Idiom: `Optional.map(...).orElse(ResponseEntity.notFound().build())`.
- **Codes:** GET `200/404`, POST `201` (+ `Location` header), PUT/DELETE `204/404`, validation `400`.
- **Cascade:** `cascade = CascadeType.REMOVE` + `orphanRemoval = true` on `@OneToMany` — Hibernate deletes the tests with separate application-side DELETEs (not a DB `ON DELETE CASCADE` constraint — visible in the SQL logs).
- **`GlobalExceptionHandler` (`@RestControllerAdvice`):** the lab 2 service-layer validation protects REST unchanged — `IllegalArgumentException` → `400` + `{"message":...}`.
- **Open Session In View:** mapping `getCategory().getName()` in a controller works because Boot keeps the JPA session open for the whole request by default; in the lab 2 console runner it would end with `LazyInitializationException`. Trade-off: convenience vs a longer-held connection and masked N+1.
- **springdoc** generates OpenAPI/Swagger UI from controller signatures alone (the Swashbuckle equivalent); `request.http` is run via VS Code REST Client (IntelliJ's HTTP Client needs Ultimate).
